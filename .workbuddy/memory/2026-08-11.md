## 合并 Google Sans Mono Italic 可变字体切片

**任务**: 将 Google Fonts CSS 中提取的 3 个 woff2 切片(latin / latin-ext / symbols)合并为单一完整可变字体,保留可变轴和 OpenType 特性。

**产出** (/Users/user/Desktop/PhiArchive/):
- `GoogleSansMono-Italic-VF.woff2` (62 KB, 428 glyphs)
- `GoogleSansMono-Italic-VF.ttf` (117 KB, 同字体转 ttf 格式)
- `GoogleSansMono-preview.html` (浏览器预览页,展示可变轴和 OpenType 特性)
- `merge_vf.py` (自定义合并脚本)

**结果**:
- 428 字形 (union: 255 + 244 + 77)
- wght 可变轴 1-1000 保留(fvar / gvar / HVAR / MVAR / avar / STAT)
- GSUB 特性保留: ccmp, frac, locl, ss01, ss02, ss03
- GPOS 特性保留: mark, mkmk (含 GDEF VarStore 可变锚点定位)
- 392 个 cmap unicode 映射

**关键难点 / 解决方案**:
- fontTools `pyftmerge` 对可变字体的 GDEF VarStore 合并支持不完整 (otTables.VarStore 没有 mergeMap)
- `instantiateVariableFont` 初始报错 "InconsistentGlyphOrder" 来自合并后 Coverage 顺序问题,通过遍历 GSUB/GPOS 所有 Coverage 转 format 1 并按新 glyph order 排序修复
- GDEF/HVAR VarStore 合并: 按 outer index 拼接 VarData.items, 记录每个字体每个 outer 的 inner 偏移, 然后重映射 GPOS device 表(VariationIndex) 和 HVAR AdvWidthMap 的 varIdx
- 验证: gvar 手动应用 wght=100/900 确认轮廓差异, 与原始 slice_1 在 wght=100 完全一致; 所有 VariationIndex 引用(1061 个)无越界
